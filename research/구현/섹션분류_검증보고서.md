# 프로젝트 상세 섹션 분류 검증보고서

> 구현과 검증을 같은 작업자가 수행한 **자체 검증** 기록이다. 구현보고서의 선언만으로 판단하지 않고 원본 데이터, 실제 그룹화 함수, production build와 로컬 브라우저 화면을 직접 대조했다. 독립된 모델의 검증으로 표현하지 않는다.

## 1. 실행 환경과 코드 검사

- Windows, 번들 Node.js, 프로젝트에 설치된 TypeScript·ESLint·Next.js를 사용했다.
- `apps/web`에서 ESLint 전체 검사: 통과, 종료 코드 0.
- TypeScript `--noEmit`: 통과, 종료 코드 0.
- Next.js production build: 통과, 네 프로젝트 상세 페이지 모두 SSG 생성.
- 변경 파일의 `git diff --check`: 통과.

브라우저 검증은 production build를 읽는 로컬 서버와 Playwright의 headless Edge에서 수행했다. 외부 배포 환경을 검증한 것은 아니다.

## 2. 데이터와 그룹화 함수 검증

네 프로젝트의 수정 전 전체 JSON과 수정 후 JSON에서 category를 제거한 객체를 깊은 비교로 대조했다. 24개 Section과 프로젝트 메타데이터가 모두 동일했다.

실제 `groupProjectSections` 함수를 실행해 다음 조건을 확인했다.

- 공통 분류 순서와 빈 분류 제외.
- 모든 입력 Section이 결과에 정확히 한 번 포함.
- 분류 내부의 기존 order 오름차순 정렬.
- 역순으로 넣고 배열과 Section 객체를 동결해도 정상 동작: 입력 변경 없음.
- 빈 입력은 빈 그룹 목록 반환, 단일 분류 입력은 그 분류만 반환.
- 누락·null·알 수 없는 category는 Section id를 포함한 오류 발생.

## 3. 실제 상세 페이지 검증

| 프로젝트 | 실제 표시 순서 | Section 수 |
|---|---|---:|
| Komit | Backend → AI → Infra → DevOps | 6 |
| DailyBand | Backend → AI → DevOps → Communication | 6 |
| Home Server | AI → Infra → DevOps | 7 |
| TeenyFinny | Infra → Communication | 5 |

각 페이지의 HTTP 200, 기존 프로젝트 제목, 분류의 H2, 모든 기존 Section의 H3와 anchor를 확인했다. 없는 분류는 DOM에 없었다. 기존 갤러리 이미지도 표시됐다.

1280px·768px·320px에서 네 페이지를 확인했고 문서의 가로 넘침이 없었다. 라이트/다크 테마에서 화면을 캡처해 그룹 제목과 본문 위계를 확인했다. 등장 애니메이션이 끝난 뒤 캡처해 중간 상태를 판정에 사용하지 않았다.

## 4. 문단 이동과 증거

- Komit의 기존 부하 테스트 anchor로 직접 진입했을 때 해당 Section이 기존 scroll margin인 약 96px 위치에 착지했다.
- 부하 테스트 비교표 버튼의 데스크톱 hover 미리보기가 실제 이미지로 표시됐다.
- 버튼을 클릭하면 기존 증거 오버레이가 열리고 이미지가 로드됐다. Escape로 닫혔다.
- 브라우저 JavaScript 실행 오류는 없었다.

## 5. 검증 범위의 한계

실제 AI 모델 응답·Neo4j 검색·외부 배포는 실행하지 않았다. 이번 작업에서 해당 코드와 그래프 데이터는 변경되지 않았으며, citation이 가리키는 기존 anchor의 보존과 실제 직접 이동을 검증했다. 갤러리 모든 슬라이드와 모든 증거를 개별로 열어 보지는 않았다.
