# CHANGELOG

## 작업 원칙

- 채용 설득력, 개발자상 선명도, 짧은 이해를 최우선으로 판단한다.
- 확인되지 않은 성과·수치·인과는 만들지 않는다.
- 프로젝트 상세를 먼저 쓰고 Home/Hero는 마지막에 압축한다.

## v0.1 — TeenyFinny 개요

- TeenyFinny의 역할을 `팀 개발에서 기준과 검증을 처음 적용한 프로젝트`로 고정.
- 핵심 사례를 계약 선행 / 요구사항 기반 선택 / DB 장애 주입 / Public 운영 도구의 아쉬움 4개로 압축.
- JWT, 인증서, HealthCheck, 발표 경험은 핵심 메시지와 중복되어 본문 우선순위에서 제외.

## v0.2 → v0.3 — TeenyFinny 퇴고

- 첫 문단에서 역할 나열을 `팀이 함께 개발할 기준과 인프라`로 압축.
- Polling 사례의 일반적인 기술 장단점 설명을 제거하고 요구사항 기준만 남김.
- DB 사례에서 `무중단` 오해를 막되 방어적인 한계 설명은 한 문장으로 축소.
- 마지막 사례를 단순 DevOps 도구 소개가 아니라 Home Server로 이어지는 실제 행동 변화로 정리.

## v0.1 — Home Server 개요

- Home Server를 `취미형 홈서버`가 아니라 TeenyFinny의 운영 문제를 다시 설계한 프로젝트로 정의.
- 접근 경계 / Docker 실제 노출 / 장애 진단·자동화 / 팀 환경 재투입 4개 사례 선정.
- Uptime Kuma, InfluxDB, 하드웨어 선택 등은 도구 나열 비중이 커 핵심 본문에서 제외.

## v0.2 → v0.3 — Home Server 퇴고

- 첫 문단을 서버 스펙 소개가 아니라 TeenyFinny 문제의 실제 후속 행동으로 변경.
- 접근 경계와 Docker 노출 사례의 중복을 `정책 기준`과 `실제 경로 기준`으로 역할 분리.
- 장애 사례를 `관측 도구를 썼다`가 아니라 진단 순서가 읽히도록 압축.
- Runner/SonarQube를 DailyBand의 AI 코드 검증 흐름으로 직접 연결.

## v0.1 — DailyBand 개요

- 대표 프로젝트의 메시지를 `AI 프로젝트 경험`이 아니라 `복잡한 시스템과 AI 결과를 계약·경계·검증으로 통제`로 설정.
- 계약 복구 / 파일 메타데이터 책임 / 직접 업로드+무결성 / AI Worker 실패 복구 / AI 코드 Quality Gate / 레이턴시 판단 6개 사례 선정.
- 게이미피케이션, 일반 기능 소개, 과잉 설계 회고 등은 대표 메시지보다 우선순위가 낮아 본문 핵심에서 제외.

## v0.2 → v0.3 — DailyBand 퇴고

- 서비스 기능 설명을 줄이고 첫 화면에서 본인 책임 범위가 먼저 보이도록 변경.
- 계약 복구에서 AI 활용을 `Agent 사용`이 아니라 `AI 초안 → 교차 검토 → 실제 구현 대조 → Mock 실행`의 검증 흐름으로 압축.
- Presigned URL 설명을 기술 장점 대신 `BE 우회로 생긴 신뢰 공백을 어떻게 메웠는가`에 집중.
- 외부 AI Worker는 패턴 이름을 붙이지 않고 commit 이후 dispatch와 Reconciler의 실제 동작만 서술.
- Quality Gate를 포트폴리오 전체의 AX 메시지를 뒷받침하는 대표 근거로 유지.
- 레이턴시는 기술명보다 `팀이 제어 가능한 구간을 골랐다`는 판단을 소제목과 본문 중심에 배치.

## Integration v0.1 — 프로젝트 간 연결

- 성장을 `배웠다/성장했다`로 선언하지 않고 다음 프로젝트에서 실제 행동이 달라진 세 연결만 작성.
- TeenyFinny→Home Server: Public 운영 문제 → 접근 경계 재설계.
- Home Server→DailyBand: 개인 Runner/SonarQube → 팀 CI/Quality Gate.
- TeenyFinny→DailyBand: 계약 우선 성공 → 계약 붕괴 비용 → 실행 가능한 계약 복구.

## Integration v0.2 — Home Projects

- Detail의 사례를 프로젝트당 판단 2개 + 확인된 결과 1개로 압축.
- TeenyFinny는 `계약 + 장애 주입`, Home Server는 `접근 경계 + 운영 재사용`, DailyBand는 `AI 계약 검증 + 책임/실패/품질`만 남김.
- 기술 목록은 프로젝트의 역할을 이해하는 최소 범위로 제한.

## Integration v0.3 — How I Work 삭제 결정

- 기준/경계/검증 3문단을 실제로 작성한 뒤 Projects와 중복 여부를 비교.
- 구체 근거 없이 행동 원칙을 다시 설명하는 섹션이 되어 최종 Home에서는 삭제.
- 핵심 단어 `계약 · 경계 · 검증`만 Hero 보조 문장에 회수.

## Integration v0.4 — Hero

- Detail에서 반복된 행동을 `계약 · 경계 · 실패 복구 · Quality Gate`로 회수.
- 백엔드 정체성은 유지하고 AX 메시지는 보조 문장에만 배치.
- `AI를 잘 쓴다`가 아니라 `AI 결과를 검증 가능한 개발/운영 흐름에 넣는다`는 실제 사례와 일치하도록 작성.

## Integration v0.5 — 전체 통합본

- Hero + Home Projects + Contact + 세 Project Detail을 한 파일로 통합.
- How I Work는 삭제 상태 유지.
- 프로젝트 카드 사이에 다음 프로젝트로 이어진 실제 행동 변화만 한 줄씩 배치.

## v1.0 — 전체 압축 및 근거 검수

- `못함` 식의 실패 결산 표현을 `프로젝트 종료 후에야 문제로 인식`으로 수정.
- How I Work 삭제를 최종 확정하고 Hero에서 `계약 · 경계 · 실패 복구 · Quality Gate`만 회수.
- 확인되지 않은 성능 개선율, 수상 사유, 완전한 무중단, Outbox 패턴명은 사용하지 않음.
- 최종 파일: `portfolio_v1.0.md` / 현재본: `portfolio.md`.
